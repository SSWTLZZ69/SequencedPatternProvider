# Sequenced Pattern Provider

一个独立的 Minecraft 1.20.1 Forge 模组，让 AE2 用一个顶层样板驱动 Create 序列组装，而不需要把每次循环的每一步拆成多个处理样板。

## 当前功能

- `序列组装样板` 记录 Create 配方、每步耗材、路由类型、循环次数和目标产物。
- `序列组装主控供应器` 有 9 个样板槽，作为 AE2 `ICraftingProvider` 同时发布多个完整配方，并按配置上限并发执行任务。
- `序列组装子供应器` 不绑定主配方或固定步骤序号，只声明背后黑盒匹配的路由标记；任意物品都可以作为标记。
- 主控、子供应器和编码终端收录在独立的“序列组装样板供应器”创造模式物品栏中。
- 主控默认通过每个步骤的 `IAssemblyRecipe.addRequiredMachines(...)` 生成路由，也允许编码时把默认机器替换成其他物品标记。
- 主控给每个工件写入独立尝试 Token，并按 Token、`SequencedAssembly.id` 与 `Step` 从 ME 网络精确认领中间件，再投向下一步。
- 概率配方自动组成固定批次；AE 只看到该批次必定得到的最低目标产量，额外目标产物和失败结果作为副产物返回网络。
- 子供应器正面只允许黑盒提取材料/流体，其他面只允许黑盒把加工结果送回；回收物会自动进入其所在 ME 网络。
- 任务和链接写入方块实体 NBT，区块卸载后可以继续。

## 玩家流程

1. 为每类加工能力搭建黑盒并放置子供应器，例如机械手黑盒、冲压黑盒。手持任意物品右击子供应器即可把它绑定为路由标记；潜行空手右击可清空列表。
2. 用 AE2 内存卡潜行右击主控保存连接目标，再用同一张卡逐个右击子供应器，把所有可用黑盒加入该主控池。卡内记录会保留以便连续连接；潜行右击空气可使用 AE2 原生功能清空内存卡。主控 GUI 中的“清空连接”按钮可移除全部子供应器连接。
3. 在序列组装样板编码终端中设置配方，或使用 JEI 的 **+** 自动填入，然后用 AE2 空白样板编码。
4. 打开主控 GUI，放入最多 9 个已编码样板，并把主控和子供应器连接到同一 ME 网络。
5. 在 AE 终端下单。主控读取当前步骤的路由标记，从绑定池中选择匹配的子供应器，并发送工件与该步耗材；路由标记本身不会被发送或消耗，黑盒必须把加工产物送回子供应器的非正面。
6. 任务卡死时，潜行空手右击主控中止；主控会退回尚未发出的材料。

内存卡也可以复制子供应器配置：潜行右击子供应器保存其路由标记、阻挡模式、锁定合成模式、输出方向和名称，再普通右击其他子供应器应用。缓冲区、当前锁定状态和运行中的任务不会被复制。

设备物品通过 AE2 的名称压印模板和压印器命名后，主控、子供应器和编码终端都会保留名称。在安装了 ExtendedAE-Plus 的整合包中，对主控或子供应器潜行使用石英切割刀时，交互会继续传给其“读取方块名称”功能；子供应器会返回实际自定义名称。编码终端作为 AE 部件沿用该附属的部件识别逻辑。

## 兼容边界

- 不维护“可用于序列组装的配方类型”白名单；Create 在解析序列配方时接受任何 `ProcessingRecipe + IAssemblyRecipe + supportsAssembly()` 的步骤，本模组沿用同一接口读取耗材和默认机器标记。
- 路由标记只用于选择黑盒，不会被发送或消耗。例如，需要按预装工具区分的机器可以使用对应工具作为标记。
- 如果某个附属步骤没有通过 `addRequiredMachines` 声明机器，可把子供应器在铁砧命名为该步骤的配方序列化器 ID（例如 `modid:recipe_type`）作为后备路由；命名为 `*` 可作为通配黑盒。
- 概率批次大小受主控并发上限约束；概率低到无法在当前上限内保证至少一个目标产物时，该样板不会发布给 AE。
- 初始工件必须允许附加 SPP 的追踪 NBT。严格拒绝额外 NBT 的自定义 Ingredient 不会被主控发布，以免破坏原配方。
- 只有走 Create 通用 `SequencedAssemblyRecipe.advance` 路径的最终结算才能主动确认空结果；静默删除工件且绕过该路径的附属机器需要专用适配。
- 子供应器是物流黑盒边界，不直接操纵机械手或传送带；玩家仍需搭建实际的 Create 加工与回流线路。

## 构建

依赖 JDK 17。项目 `libs/` 内固定放置当前目标版本的 AE2 15.4.10、GuideME 20.1.14 与 Create 6.0.8 开发依赖；GuideME 是 AE2 15.4.10 的强制运行依赖。

```powershell
./gradlew.bat build --no-daemon
```

输出位于 `build/libs/sequenced_pattern_provider-1.20.1-0.3.1.jar`。

## 开发测试配方

这些配方使用创造模式专属物品作为初始工件，不会给正常生存流程增加低成本产物：

| 配方 ID | 初始工件 | 目标结果 | 用途 |
|---|---|---|---|
| `sequenced_pattern_provider:test/deterministic_deploying` | 调试棒 | 苹果 | 机械手、额外耗材与循环 |
| `sequenced_pattern_provider:test/probability_80_pressing` | 结构空位 | 钻石 80% / 燧石 20% | `5 → 至少 4` 概率批次 |
| `sequenced_pattern_provider:test/probability_18_2634_pressing` | 拼图方块 | 绿宝石 18.2634% / 煤炭 81.7366% | `11 → 至少 2` 非整齐概率 |
| `sequenced_pattern_provider:test/probability_empty_pressing` | 屏障 | 下界之星 50% / 空结果 50% | 无物品返回时的主动完成通知 |

可以使用以下命令取得足够完成一个批次的初始工件，再从苹果、钻石、绿宝石或下界之星的 JEI 用途页面找到对应序列组装配方并点击 **+**：

```mcfunction
/give @s minecraft:debug_stick
/give @s minecraft:iron_nugget 2
/give @s minecraft:structure_void 5
/give @s minecraft:jigsaw 11
/give @s minecraft:barrier 2
```
